### 本版增加的完整流程

连续设施覆盖 → 缺失数据定向补查 → 1至3处补点方案 → 三条件取舍 → 绕行核查清单 → 固定抽点复核。每一步保留来源、未知与原报告。

> 构造数据验证计算与流程，真实API核对供应商结果，现场实走验证现实通行。本版具备前两类；尚无新增现场真值。

## 03 从社区问题，到一次具体行动

距离近不等于走得到。绕行、过街、入口、个人步速和等待会改变可达范围；仅看直线圆无法直接解释这些差别。社区还需要知道：空白来自设施缺少，还是资料没有查全。

1. 选一个中心：输入真实社区地址或坐标；首次可用人工路网示例，不需要密钥。
2. 看范围与设施：以路线测时生成5/10/15分钟范围，查看六类设施与分类覆盖。
3. 把空白接到核查：查看完整性、最近设施及来源；选择补查，比较前后并明确采用。
4. 把假设接到验证：比较候选补点与不同步速，再用分离位置复核原预测，导出完整依据。

### 居民和协助者如何使用

居民可记录地图未收录的小店、核算含返程的一趟出门。老人可用简易模式、大字地点与已保存指引；家人协助按次开启，建议由本人确认。跨网络同步与协助需要共同的HTTPS服务。

## 05 把有限调用投向时间边界

不下载底层路网，以API步行测时作为观测。默认中心四周1600米、400米粗网格，共81顶点；两轮加密总预算最多96点，优先跨5/10/15分钟阈值的边。

| 步骤 | 做法与边界 |
| --- | --- |
| 共享边细分 | 测得中点后同时细分相邻三角片，避免悬挂顶点；第二轮优先5分钟边界。 |
| 阈值插值 | 只在三个顶点均有效时线性裁切，合并片区并保留孔洞与断开区域。 |
| 未知与截断 | 缺测不填0，不用凸包跨空白；触及采样边缘提示范围可能被截断。 |
| 设施可达 | 设施仍用中心至设施的路线耗时判断，不用是否落在插值多边形内代替。 |

### 边上交点

> p = pA + (T - tA) / (tB - tA) × (pB - pA)<br/>同一组测时生成多个阈值，交点局部坐标量化到毫米以减少数值接缝；该数值处理不代表现实定位精度。

等时圈、插值和自适应采样都有既有研究。本项目的实现增量是预算调度、共享边一致性、失败边界及复算流程。未采到的围墙仍可能造成误差，必须保留独立点和现场检验。

## 06 设施缺口，与证据不足分别显示

六类设施为菜市场、药店、小学、医疗、公园与养老。优先同类UID去重；缺UID时结合规范化名称和30米邻近规则，同名不同UID分店保留。核查资料保留来源、观察日期、分歧与撤销。

| 口径 | 回答的问题 | 依据 |
| --- | --- | --- |
| 15分钟路网 | 中心能走到哪些设施？ | 中心至设施的步行耗时 |
| 1公里覆盖 | 核查点附近有没有三类必需设施？ | 已检索设施直线距离、类别完整性和完整邻域覆盖 |

| 分区 | 含义 |
| --- | --- |
| 已找到设施 | 已有可用同类设施提供正向距离证据；圈外设施也可影响圈内覆盖。 |
| 候选缺口 | 分类检索完整且邻域足够，仍未找到同类设施；现实情况待核查。 |
| 待核查 | 分页/范围不足、未知或边界保留带；不判为现实缺少设施。 |

连续分区保留孔洞、断开片区和距离边界；128边内外近似将保留带归入未知。四组固定几何对照共23,428点，无错误已覆盖或错误缺口；只证明构造几何，不证明POI收录完整。

> 同样的三色状态、面积及逐点依据用于Web和微信。面积不代表人口覆盖率，也不代表从新设施出发的真实路网服务区。

## 07 缺失资料，转成有界补查任务

<b>先选最多三项</b>
缺失测时、局部一类设施检索或现场入口任务分别列明。

<b>先预览，再执行</b>
显示含一次重试的上限，复用原网关；不重新跑整个社区。

<b>先看差异，再采用</b>
比较范围与未知的变化，采用前保存最近一组前后报告。备份失败则保留草稿。

### 局部证据只证明它覆盖的范围

一个完整查询必须覆盖核查点整个1公里邻域，才能支持该点的负向结论。不能把多个未查全的小范围拼成完整。新位置与旧位置有明显分歧时保留旧坐标并提示待核实，基础资料时间不被新生成时间替换。

> 构造演练有效测时176→177、未知面积约0.848→0.210 km²，同时范围也改变。该演练不是上海改善成效。导出包含完整前后输入，支持独立复算。

## 08 同样增加几处，哪种方案补得更多

从已有测时点选择1至3处候选，枚举最多7个单点／组合方案。只在相同新增数量内比较，扣除重叠覆盖，未知区假设覆盖单列，原设施统计不变。

| 比较对象 | 结果必须说明 |
| --- | --- |
| 一处对一处 | 已知候选缺口新增覆盖面积；不把未知区覆盖计入收益。 |
| 两处组合 | 先合并几何再算收益；说明相对少一处方案增加多少。 |
| 三处组合 | 唯一组合不能宣称在同数量中胜出；无收益时不强行推荐。 |

### 范围与可建设性是不同问题

服务影响复用1公里距离口径和保守边界，不是新设施的实际路网服务区；没有土地、商户意愿、容量和建设成本信息。输出是核查候选位置的假设比较，不能作为建设承诺。

> 固定构造验证包含重叠、未知、相同数量、孔洞与边界，原始输入及几何随源码保存。Web导出文件交给Node重算，微信可复制位置、来源与计算口径。此功能不新增API请求。

操作：设施核查 → 比较设施补点方案 → 选点 → 比较 → 切换组合 → 导出。详细面积和坐标按需展开，手机默认先显示结论与关键数值。

## 09 换种走法，比较方案的取舍

同一候选位置，分别按原步速／时段、对照步速／时段、再加固定等待计算。三组均复用已有路线距离，等待由用户假设。

在各条件内找同数量最好收益，再看方案最大一次落后；不按概率投票。

三组共同补足取空间交集，不能用最小面积冒充同一片区域。各组范围、缺口与未知分别列出。

| 构造反例 | 原步速收益 | 较慢步速收益 | 最大落后 |
| --- | --- | --- | --- |
| A | 443,564 m² | 7,407 m² | 28,058 m² |
| B | 305,944 m² | 35,465 m² | 137,620 m² |

该构造反例中首选随条件变化；总体取舍较小不等于更适合慢行人群。无人口权重，只有所选位置枚举，不是全局最优。

读取已有采样及设施路线，同坐标去重，区分缺测、未连接、记录分歧和异常。直线圈仅筛选附近对照点，仍以原路网轮廓作可达范围。

| 线索条件 | 门槛与解释 |
| --- | --- |
| 避免小分母 | 直线距离至少80米 |
| 距离代价 | 路线比直线至少多200米 |
| 相对代价 | 路线至少达到直线1.5倍 |
| 行动 | 默认三条、最多八条清单，带坐标现场核对入口与过街设施 |

### 上海已有报告的回放结果

177点报告中，按直线对照半径筛选与去重后有144个有效已测点；其中37个按记录用时超过15分钟，26条满足距离绕行门槛。本次小学补点方案的已知缺口收益仍为0，如实不推荐。

> 26条是核查线索，不是26处已确认障碍。没有路径形状与现场资料时，不能推断围墙、河流、施工或具体路口原因，也不能给出捷径。点数不代表面积或发生率。

距离门槛是核查次序的启发式，尚未按现场障碍标注校准。地图端点吸附、入口、坐标和记录时间均可能影响判断。此诊断复用历史数据，零新增API调用。

## 13 居民的一趟出门，连起时间与费用

用户选买菜、取药或逛公园，设置整趟上限与购物预算。规则引擎核算有方向差异的路线、停留、营业等待和返程。私人价格按规格匹配，缺价、过期和缺货直接显示。

1. 先核算，再出门：比较少走、少花与均衡安排；缺价不是零元，换店不沿用旧价。
2. 顺路动一动：在已选路线安排轻松或交替节奏，重算等待与返回时间，不记作实测运动。
3. 途中有变化：结合入口反馈比较同类地点或本人确认的另一入口，由本人确认替换。
4. 带一张出门卡：保存返程、入口与已获取步骤；Web下载独立离线文件，不依赖持续联网。

### 实走记录帮助校准个人步速

先保存预计用时，再补记实际用时并扣除等灯与停留。至少3条、300米合格记录才给建议，由本人采用；后续新记录成对比较误差。两端已有实现与四组构造对照，尚无现场人群效果证据。

> 价格来自私人记录，不是实时均价；替换目的地不等于自动绕过任意障碍。示例路线和价格持续标记为构造数据。

> 跨网络位置卡与远程协助依赖共同HTTPS服务。缺少服务器时仍可读取本机资料、打印或复制指引；当前没有公开求助定位服务或定位准确性保证。

# 界面设计约定

## 产品认知

新建地图分析工具，面向居民、社区工作者和评审。核心对象是分析中心、步行时间、设施分类、可达范围和体检报告。首页直接进入工作台，第一步选择地点，成功标准是看懂附近设施与缺口并能导出报告。

入口为离线样例或真实地图；错误可通过换地点、重试或补齐接口配置恢复。手机主要操作为选点与开始体检，地图和报告按任务顺序切换。产品语气清楚、亲切，不用基础设施术语代替用户动作。

## 技术与布局选择

选用 React + Vite、原生语义表单和项目 CSS；相较完整后台组件库，更适合只有少量控件、地图占主要面积的工作台。参考地图工具的覆盖物图例和 GOV.UK 的清晰表单反馈，不引入管理后台菜单。

比较过“旅游宣传首页”和“数据大屏”方向后，选择社区地图工作台：顶部短品牌栏，左侧地点与时间操作，右侧大地图；设施清单与报告紧邻结果。手机保留地点、时间和开始按钮，报告独立切换。

## 视觉

- 墨绿 `#146c5d`：主动作和可达范围。
- 深蓝灰 `#243f48`：正文、标题。
- 雾白 `#f4f8f7`：页面背景。
- 白色 `#ffffff`：控件与结果面板。
- 柔橙 `#c46136`：分析中心和重点标注。
- 中灰 `#64777c`：次要说明与未知范围。

中文品牌以宋体字形体现生活感，功能和数据使用系统无衬线体，数字等宽。8px间距节奏，控件至少44px高，圆角10px，聚焦描边清楚。保留地图上的5/10/15分钟层次作为视觉特征，不增加无关装饰。

## 状态与验证

离线示例持续标记“模拟街区”，不能让真实案例地名与模拟设施混淆。未知与不可达分开；不以颜色作为唯一状态提示。包含初始、计算中、成功、无设施、部分数据、接口未开通、请求失败状态。

验证1280px桌面、390px手机、键盘操作、图例筛选、报告导出、错误恢复与页面无横向溢出。界面不显示密钥、原始请求、模型名或开发过程说明。

## 结果回放与覆盖增强

历史结果保留生成时间和来源，默认以原坐标示意回放；主动加载真实底图后才产生地图资源请求。导入失败或重新体检失败都保留已有结果。保存记录仅在当前浏览器，提供移除撤销和文件下载。

覆盖图表展示已发现、未检索到、数据不足三种状态，保留数字和说明。灰色网格按类别切换，裁剪到选定轮廓，不能被描述为精确缺口面积；采样点比例不代表人口覆盖率。预算详情保持折叠，显示本地计数的范围，不声称掌握账户余额。

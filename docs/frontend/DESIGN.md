# 界面设计约定

## 产品认知

新建地图分析工具，面向居民、社区工作者和评审。核心对象是分析中心、步行时间、设施分类、可达范围和体检报告。首页直接进入工作台，第一步选择地点，成功标准是看懂附近设施与缺口并能导出报告。

入口为离线样例或真实地图；错误可通过换地点、重试或补齐接口配置恢复。手机主要操作为选点与开始体检，地图和报告按任务顺序切换。产品语气清楚、亲切，不用基础设施术语代替用户动作。

## 技术与布局选择

选用 React + Vite、原生语义表单和项目 CSS；相较完整后台组件库，更适合只有少量控件、地图占主要面积的工作台。参考地图工具的覆盖物图例和 GOV.UK 的清晰表单反馈，不引入管理后台菜单。

比较过“旅游宣传首页”和“数据大屏”方向后，选择社区地图工作台：顶部短品牌栏，左侧地点与时间操作，右侧大地图；设施清单与报告紧邻结果。手机保留地点、时间和开始按钮，报告独立切换。

## 视觉

- 墨绿 `#146c5d`：主动作和可达范围。
- 深蓝灰 `#243f48`：正文、标题。
- 雾白 `#f4f8f7`：页面背景。
- 白色 `#ffffff`：控件与结果面板。
- 柔橙 `#c46136`：分析中心和重点标注。
- 中灰 `#64777c`：次要说明与未知范围。

中文品牌以宋体字形体现生活感，功能和数据使用系统无衬线体，数字等宽。8px间距节奏，控件至少44px高，圆角10px，聚焦描边清楚。保留地图上的5/10/15分钟层次作为视觉特征，不增加无关装饰。

## 状态与验证

离线示例持续标记“模拟街区”，不能让真实案例地名与模拟设施混淆。未知与不可达分开；不以颜色作为唯一状态提示。包含初始、计算中、成功、无设施、部分数据、接口未开通、请求失败状态。

验证1280px桌面、390px手机、键盘操作、图例筛选、报告导出、错误恢复与页面无横向溢出。界面不显示密钥、原始请求、模型名或开发过程说明。

## 结果回放与覆盖增强

历史结果保留生成时间和来源，默认以原坐标示意回放；主动加载真实底图后才产生地图资源请求。导入失败或重新体检失败都保留已有结果。保存记录仅在当前浏览器，提供移除撤销和文件下载。

覆盖图表展示已发现、未检索到、数据不足三种状态，保留数字和说明。灰色网格按类别切换，裁剪到选定轮廓，不能被描述为精确缺口面积；采样点比例不代表人口覆盖率。预算详情保持折叠，显示本地计数的范围，不声称掌握账户余额。

## 设施核查

在已有报告中增量提供核查表单，面向社区使用者与材料整理者。入口紧邻设施明细，先选设施，再记录来源和结论；成功标准是记录可追溯、统计随之更新、能保存和撤销。保留现有React原生表单、墨绿配色和GOV.UK式明确反馈，不新增后台导航。手机表单单列、主要动作为记录核查；导入预览、错误保留原报告、撤销、刷新回放和打印附录均纳入浏览器验证。不同来源的冲突显式展示，产品文案不把使用者提供的记录说成平台认证。

## 日常出行与协助者

项目处于已完成体检主流程后的功能扩展阶段。新增表面是居民日常任务页，核心对象为私人地点、入口地标、出行偏好和共享报告。入口为“我的日常”，第一选择是记录/查找地点、修改出行偏好或同步设备。成功标准是能重新找到小店，协助者能打印清楚的大字卡，两端不会互相覆盖未同步记录。

保留现有配色、字体、React原生表单及地图工作台。地图控制器不重建；“我的日常”在手机上收起分析侧栏，以地点与指引、出行偏好、设备与同步三个入口减少长页翻找。信息优先级为地点名称与入口、操作反馈、来源与数据限制。大字卡不显示设备令牌、服务协议或模型内部名称；账号连接细节放到专门入口。模拟地点始终明示。

大字卡的视觉特征为左侧墨绿边线与大号地点/地标，家属打印后可直接交给老人。服务未连接、位置授权拒绝、存储失败、无地点、数据冲突都有文字恢复方式。删除、导入与合并保留撤销；私密配对码不进入分享链接。验证桌面、390像素手机、键盘焦点、无溢出、打印仅包含卡片、旧报告兼容以及零付费调用。

## 微信日常入口

微信保持原生JS/WXML/WXSS，三个底部入口为附近、地点簿、我的。附近优先呈现步行时长、地图范围、分类与按用时排序的目的地；地点簿以快速保存入口为主要动作，照片与详细提醒按需展开。服务器地址和配对放在“我的”，无服务器时示例和草稿仍可用。

沿用墨绿和浅底色，使用已经选定的“15”道路头像。大字模式提升名称、表单与按钮字号，地点卡突出名称、入口照片、地址和地标；不把卡片说成逐路口导航。分享前明确只读范围、有效期与转发性质，接收页不包含整个地点簿的修改入口。

布局预检覆盖320像素大字、390像素附近与记店表单。转译WXML的浏览器预览只用于检查排版，不作为原生地图、相机、授权和转发的验证证据；这些必须在实际微信开发者工具和安卓/iOS中继续验收。

## 出门办事

这是既有产品的功能扩展，保留配色、原生微信页面和React表单。入口独立于体检参数，四个任务标签只显示当前场景；先选要办的事，再看时间线结果。手机的出发设置与营业时间折叠，计算完成定位到结果，切换任务回到功能入口。结果附带模拟标记、时间门槛或连续步行上限，避免截图脱离输入条件。

熟路查看时隐藏编辑表单，突出编号地标、照片和下一步按钮；编辑草稿自动保留，新建或切换编辑对象前提示草稿替换。Web提供整条路线的白底打印。过期休息点不可选择，缺失路线与无可行方案分别提供恢复说明。同步预览同时展示三类私人记录的数量。

保留44像素及以上操作区和可见键盘焦点。验证覆盖桌面、390像素和320像素Web布局、打印、大字原生模拟器；记录中所有路线和入口示例均标记为构造数据。真实手机新增流程和现场核验单独进行。

## 顺路好买

购物是“一趟办齐”的子任务，复用现有React、原生微信表单和墨绿配色。两个入口为购物清单与价格记忆，核心动作为比较购物方案；收据式结果突出预计金额、返回时刻、各站购买清单与推荐理由。候选店和出发条件折叠，商品先显示名称、规格和数量，编辑时只展开当前条目，避免手机首屏连续出现长表单。

参考消费、商品单价与已知部分分别标注；模拟价格、失效日期、当前库存待确认和预算状态用文字表达。删除可撤销，失败保留输入，存储失败不报告成功，缺价不按零元比较。原生大字模式表单单列、输入框至少104rpx，常规至少88rpx；官方模拟器截图核对输入高度、搜索容器和结果阅读。浏览器额外检查缺少剪贴板能力时的提示与320像素布局。

## 顺路动一动

已完成产品上的移动任务扩展，面向居民及协助出行的家人。核心对象是已选行程、本人舒适步速、分段节奏与时间约束。入口从办事／购物方案进入，也保留明确标注的离线示例；第一步选择轻松走或轻快交替，手机主动作是“安排这一趟怎么走”。成功标准是保持已选地点顺序，重新算清步行、等待、停留和返回时间，能看到目标不足或预算不满足的原因。

继续使用React与原生微信表单、墨绿视觉和GOV.UK式明确反馈。信息顺序为适用状态、计划步行量、返回时刻、分段节奏；参数细节折叠。切换条件保留输入，错误不产生完成记录。保持44像素操作区、大字模式和键盘焦点。不得把路段示意当作路口导航、步速当作个人健康诊断、计划当作实测运动，或把本机规则标为大模型结果。核验边界时间、等灯跨峰谷、营业等待、负重返程、歇脚、两端同步、320像素与微信原生显示；不新增地图调用。

按上述约定完成桌面、390与320像素Web核验，以及原生微信大字表单、结果和展开节奏截图检查。购物结果的步行入口独占一行，避免与复制和价格补记挤在同一行；结果把目标不足与时间不可行分开表达。没有现场测量依据时，不加入卡路里、健康强度或实际运动完成状态。

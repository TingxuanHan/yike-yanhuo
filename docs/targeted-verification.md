# 定向补核查与结果说明

2026-10-16。将报告中的数据不足接到明确的补查动作。Web与微信共用任务、局部检索证据、差异与解释规则；本轮不新增依赖。

## 操作

1. 打开社区体检报告 → 设施核查 → 展开“补齐缺失数据”。
2. 查看缺失步行测时、局部同类设施检索，以及需要现场确认的入口/营业清单。一次选择1至3个接口任务。
3. 先点“查看补查用量”。预览不调用百度。真实模式显示包含一次重试的测时条数与检索次数上限，确认后才执行；缓存命中时实际消耗可能更低。
4. 任务完成后同时看有效测时数、新增设施数、待核查面积与步行范围面积。补齐测时可能扩大轮廓，不能只用未知面积的增减评价改善。
5. 先导出或复制依据，再决定是否“采用补查结果”。采用前保存最近一组前后报告，备份失败则原报告和待采用结果都保留。可以恢复上一份报告或打开最近备份。

模拟报告可以点击“体验模拟缺测”，刻意移除一个测时，并将一类检索设为不完整。微信演练完全在本机运行，不需要服务器。社区演示中的临时操作不写入私人地点簿、报告缓存或补查备份；退出演示恢复原报告和偏好。它不能充当上海真实测试。

现场清单只提出要确认的事情，不会将地图查询标为实地核验。Web可导出清单，再使用既有设施核查功能记录来源、日期和依据；微信显示清单。私人照片、家庭位置和联系方式不会自动公开。

## 局部证据如何进入原报告

原报告的`complete`、检索半径和历史测时仍保留。新字段`localSearches`分别记录类别、查询中心、半径、返回是否取完和读取时间，最多12条。只请求所选类别，分页上限沿用服务端现有配置，不提高并发或日额度。

某个核查点只有在完整的单次查询覆盖其整个1公里核查邻域时，才能用该查询判断候选缺口。连续分区先分别将每个完整查询圆缩入核查距离，再合并这些有效核心；不能先把多个不完整范围拼起来，再当作完整检索。距离近似保留原来的内外边界规则，孔洞和断开区域继续保留。

- 找到可用同类设施是正向证据，不要求类别整体完整。
- 返回未取全、含无效条目、越界、位置差异或邻域覆盖不足时，空白继续标为待核查。
- 发现原有设施的返回位置相差超过5米时，保留原坐标和历史记录，追加“待核实”依据，暂停用它证明覆盖。5米是复核触发规则，不是定位精度结论；既有人工核查记录不会被覆盖。
- 新发现的设施本轮不会自动追加步行测时；没有可复用测时的设施留待下一轮主动选择。
- 同一位置已有有效测时可直接复用。个人试算报告的新测时使用距离与既有偏好计算一次，同时保留原始接口秒数。

任务按关联缺测片区进行粗略排序。测时任务只关联该点实际缺测的三角片，已测网格不会被算成待修复面积；局部检索任务按已有轮廓内可能涉及的待核查区域排序。不同任务的关联范围可重叠，不是可相加的预期收益，也不是全局最优核查计划。

## 报告版本、备份与恢复

`verification`记录直接来源报告、来源生成时间、完成时间与每项任务的结果。`baseGeneratedAt`持续保留最初基础资料的时间；新的`generatedAt`只代表补查报告生成，不能把所有历史设施和路线说成刚刚重新核验。

补查不更换已有路线寻优方法，也不自动补采其他网格或扩大整份报告。未获得有效路线时保留未知/不连通说明；未完成或取消的任务不发布部分报告。

普通使用中，`yike-last-verification`保存在各设备本机，最多一组前后报告；新的采用会替换上一组备份，建议先导出。它不会自动同步整个备份包。补查后的单份报告仍可使用既有共享报告接口交给另一端。Web导出包含完整前后报告；微信可以复制带来源的摘要，在本机恢复原报告。

接口请求使用原报告摘要和请求编号绑定。网络恢复后重复提交同一个编号返回同一个任务，内容变化则拒绝。编号保护随服务器内存任务保留，最多10分钟；不是跨重启的永久幂等记录。修改报告、类别、时长或任务选择会清除旧预览。页面离开或停止后忽略迟到结果；已发出的调用可能已经计入用量。

## 补点结果页

Web与微信先显示有依据的单点比较结论，再显示紧凑方案选择、前后图和三项关键面积。坐标、完整分区和计算依据按需展开。组合方案会说明相对当前最佳少一处方案的额外增益，避免将重叠覆盖当成新增价值。

结论来自现有面积计算，无模型请求。单点结果相差不足1000平方米时提示“补足面积接近”，这是当前显示尺度下的提示，不是统计等价或真实选址可行性判断。没有已证实的原缺口时，不输出收益优选结论。原始几何、完整导出和相同新增数量的比较规则继续保留。

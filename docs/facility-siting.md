# 设施补点方案比较

2026-10-16。将连续设施缺口接到具体位置假设：选择1至3个已有测时点，比较单点及组合方案，共最多7种。Web与微信使用同一计算实现，不新增地图检索、路线、模型或语音请求。

后续结果页增强：先显示由计算规则生成的单点比较结论，再显示紧凑方案、地图与三项关键面积；组合解释相对少一处方案的额外收益。坐标与完整面积保留在依据内。无已证实缺口时不做收益优选，显示尺度内相差不足1000平方米时提示接近，不代表统计等价。当前221项业务、40项浏览器流程通过，验证细节与补证闭环见[定向补核查](targeted-verification.md)。

## 使用

1. 社区体检 → 体验模拟社区，或打开已有报告。
2. 设施核查 → 选择菜市场、药店或小学 → 展开“比较设施补点方案”。
3. 从当前时长内已有路线测时的核查点选择1至3个不同位置，名称附相对出发点的方位和距离。
4. 点击“比较所选方案”。单点、两点、三点分组，在相同新增数量内按补足原缺口面积排序；点击方案查看分区图，再切换补点前后。
5. Web可导出含原报告、候选坐标、全部方案和算法版本的JSON；微信可复制含来源、坐标和限制的摘要。

候选点不代表有空置店铺、可用入口或规划许可。当前界面仅选择报告中的测时点，暂不接受任意地图点击或将私人店铺直接加入公共设施。原“补点看变化”用于少量点到店的步行对照；本功能比较整个已有轮廓内的直线邻近面积，两种口径分别保留。

## 计算与证据边界

原分区包含已有设施覆盖C、候选缺口M和待核查U。每个候选点使用与连续覆盖相同的保守距离内边界F，组合方案先求各候选F的并集H。

- 假设补足的原缺口：M与H的交集；只有这一项计入缺口改善。
- 待核查区内的假设覆盖：U与H的交集，单列，不将缺失证据变成已证实缺口。
- 原缺口未计入补足：M减H。包含保守距离边界，不能称作已证明新增设施无法覆盖的精确范围。
- 其余待核查：U减H。已有设施覆盖C保持原值。
- 重复计入面积：单点缺口增益之和减组合增益；三点重复区域可能原本累计三次，此项是扣除的重复计数，不是另一片独立区域。

五类分区互不重叠，合计等于当前轮廓面积；孔洞与断开片区保留。距离门槛读取报告参数，沿用128边保守内边界。距离近似、坐标、POI遗漏、路网插值及入口误差不能混为一个精度数字。面积不表示受益人数、实际营业或到店步行距离。

检索不完整导致没有已证实候选缺口时，即使假设覆盖很大，各方案已证实的缺口改善仍为0。无轮廓、无候选、重复位置或无效参数给出恢复提示；改候选、类别、时长或报告后清除旧比较。原报告和公共设施不会被修改。

## 验证及复现

```sh
npm ci
npm run build
npm test
npm run test:ui
npm run benchmark:siting
# 对Web导出的比较文件进行本地面积复算，不调用外部API
npm run benchmark:siting -- --replay=path/to/yike-siting-school-15.json
```

- 全量208项业务/API/原生页面测试与38项浏览器流程通过。新增验证覆盖七方案、重叠扣除、未知与检索边界、孔洞、重复点、空轮廓、原报告不变、编辑失效及双端同值。
- [固定构造验证](experiments/facility-siting-simulation.md)：4个场景、每场景7种方案，共163,996个点与方案组合检查；错误缺口改善、超出距离的假设覆盖及分区错误均为0。不是163,996个不同实地点，也不是现实社区准确率。面积守恒误差低于0.001平方米，完整输入和每方案结果见同名JSON。
- 浏览器导出后由Node重算面积。运行时三角函数末位浮点值可能不同，面积校验容差为0.001平方米；这是复算数值容差，不是现实规划精度。发现约5.8e-11平方米的差异后，将校验从逐位相等改为明确容差，未放宽业务分类。
- Web核验桌面、320/390像素、标签、前后切换、导出、重复选择恢复和类别变化；修正选择器标签与全局描述列表样式覆盖。
- 微信官方命令行核验标准/大字页面、比较后滚到结果、选择方案后滚到图及面积摘要。截图为构造社区模拟器，未使用桌面控制；新增实体手机和现场选址验收待完成。

入口源码：`src/core/facility-siting.ts`、`src/client/FacilitySitingPanel.tsx`、`miniprogram/pages/home/`。不新增依赖，不改变真实API并发与配额。

# 自然语言规划助手：接入选择

当前已实现购物、办事、休息与步行节奏的程序计算。本文件是下一步接入方案：尚未接通模型、创建云环境、增加密钥字段或发送用户数据。离线规则正常使用，界面不会将规则输出标成模型生成。

## 最先值得做的能力

输入一句话，例如“带50元买菜，45分钟内回来，想顺便走20分钟，买完东西慢慢回家”。助手整理成可修改条件：购物预算50元、整趟45分钟、步行目标20分钟、返程轻松。缺少的商品、规格、可接受步速仍由使用者补充，不从年龄或一句话猜测个人健康能力。

使用者确认条件后，现有程序核对候选商品与价格记录、已读取路线、停留、营业窗口、歇脚点有效期和时间预算。模型可以说明几种方案的取舍，如“这个方案少花钱但多走一段”；金额和分钟数必须来自程序结果。找不到能满足要求的方案时，明确哪一项条件冲突，再让使用者决定是否调整。

## 三种提供方式

| 方式 | 如何接入本项目 | 适用阶段与代价 |
| --- | --- | --- |
| 现有Node后端转发模型API | 增加可替换的供应商适配器，Web与微信共用；密钥只放后端 | 改动较少，适合先完成比赛演示。模型用量按供应商规则计费，后续公开使用仍需要可达的HTTPS后端 |
| 微信云开发／CloudBase | 云函数处理自然语言、校验结果并提供给两端；也可使用云开发的模型接入能力 | 适合正式让多台手机使用；需开通环境、配置认证和用量上限。原SQLite业务后端并不会因此自动迁移 |
| 本机Ollama运行模型 | Node后端调用本机模型服务，再返回已校验条件 | 适合离线演示和较少外传数据的场景；要下载模型，速度取决于电脑。手机需要访问这台电脑提供的后端，不是小程序直接在手机运行模型 |

建议先用第一种，保留第三种作为可选适配器。参加演示时核心功能仍可以离线运行；进入公开使用阶段，再根据服务器方案决定是否用云开发承载模型请求。

截至2026-10-08，腾讯云官方文档列出小程序、Web、Node及HTTP调用方式，支持内置模型与自定义模型供应商；具体资源包、资格及费用需以所选账号控制台为准，不能默认免费。[CloudBase AI文档](https://cloud.tencent.com/document/product/876/130727)

Ollama官方API同时支持本地与云模型；本机模型服务地址为`http://localhost:11434/api`，调用已下载的本地模型不需要云端API密钥。只由项目后端访问本机模型端口；公开客户端仍经过项目鉴权。[Ollama API说明](https://docs.ollama.com/api/introduction)

## 边界与用量设计

模型解析器只返回白名单结构，例如`tasks, shoppingBudget, tripMinutes, movement, clarification`，并绑定本次候选数据版本。商品、店铺和路线只能引用当前候选中的编号；不接受模型返回的新坐标、价格、实际信号时间、营业事实或未经核验的无障碍结论。返回值通过同一套业务校验，不直接执行模型给出的URL、脚本或任意工具。

界面先展示可编辑的条件卡，再点击计算。涉及新的地图读取仍走原额度确认和串行队列；语言解析不会自行触发路线接口。模型故障或达到限额时回到表单，保留输入。

每次主动请求先只调用一次模型做条件提取，解释阶段优先用程序模板；有必要时最多增加一次受限解释请求。后端单独设置每空间每日次数、输入输出长度、总Token预算、超时与供应商消费告警，缓存相同条件，限制重复点击，不让模型自行循环探索路线。地图额度与模型额度分别计数。

发送给模型的是使用者本次输入、必要偏好、匿名候选编号及价格／时间摘要。默认不发送家庭精确地址、照片、整本地点簿或健康信息。产品需提供发送范围说明；调用日志保存状态、延迟、用量，不保存密钥和完整私人输入。

接入前只需确定模型来源、演示或公开使用范围，以及可接受的每日花费上限。API密钥后续放入本机或服务器配置，不粘贴到聊天或提交仓库。验收重点是模糊条件澄清、虚构候选被拒绝、超额停止、超时回退、用户确认前零地图调用，以及Web／微信结果一致。

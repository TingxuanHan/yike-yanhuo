# 一刻烟火技术报告

版本0.1.0，增强版开发记录，2026-10-05。本文区分已实现能力、合成验证、API留出对照与待完成的现场核验。

## 1. 目标与问题定义

输入一个社区分析中心，输出5、10、15分钟近似步行可达范围、范围内六类民生设施及需要进一步核查的覆盖点位。研究对象是步行路线耗时，而非简单的直线半径。当前“规划助手”提供设施核查线索，不提供自动规划审批结论或人口加权选址优化。

设施包括菜市场、药店、小学、医疗、公园、养老。首版通过每类一个关键词查询；医疗当前查询社区卫生服务中心，养老查询养老服务。分类召回并不等于完整设施普查。

## 2. 架构与边界

React/TypeScript工作台负责选点、图层、列表、报告和导出；Node.js服务负责参数校验、任务生命周期、上游访问与计算。核心分析不依赖地图界面，模拟提供者与百度提供者共享同一流程和结果模型。

地图绘制通过JSAPI 4.0。两种AK只保存在服务端本地环境中；网页先声明代理地址，再请求本项目地图资源端点。代理固定上游域名、限制绘制资源路径、注入AK与官方代理请求头，不向前端返回配置密钥。

## 3. 坐标与采样

真实位置统一使用BD-09，经度、纬度分别存储。步行与地点接口按文档使用“纬度,经度”；坐标转换使用“经度,纬度”。局部计算采用以分析中心为原点的等距圆柱近似，适用于社区尺度，不用于城市或全国面积测算。

默认采样范围为中心向东西南北各1600米，粗网格400米，共81个顶点。网格单元拆为三角形。每次最多新增96个采样点：首轮最多使用预算的三分之二，对跨越300、600、900秒阈值的三角形测边中点；第二轮将剩余额度用于5分钟边界，局部名义间距可达100米。中点同时分割相邻三角形，保持共享边一致。预算不足时保留较粗网格并说明。

## 4. 可达范围构建

若三角形三个顶点均有有效步行时间，按时间阈值截取其内部区域。对边上时间分别为`t_a`、`t_b`的端点`p_a`、`p_b`，交点为：

`p = p_a + (T - t_a) / (t_b - t_a) * (p_b - p_a)`。

交点量化到毫米以消除相邻边反向插值造成的浮点接缝，随后合并三角片。保留孔洞与分离片区，不使用凸包跨越未知区域。任何顶点为未知或不连通的三角片不插值。若可达采样点触及范围边缘，报告提示结果可能截断。

插值仍可能跨越未采样到的围墙、封闭院落和局部水面；加密预算有限。多边形内任意一点不等于严格可走位置，仍需以独立路线点和入口核验估计误差。

## 5. 设施清洗与覆盖

优先按同类别UID去重；UID缺失时以规范化名称及30米邻近规则去重。保留不同UID的同名分店，跨类别设施分别呈现。非法或越界位置不进入统计，并使分类完整性标志失效。

每类默认只取10条、1页，以控制个人检索日额度。只有明确返回总数、已取全、未达到150条总量上限且无无效条目时，才标记该次检索已取完。标志表示返回结果完整，不能证明现实中的设施完整。

设施数量根据中心到设施的真实步行耗时计算，不用其是否落在插值多边形内替代路线判定。对15分钟可达采样点检查1公里直线距离内的菜市场、药店、小学；检索半径覆盖该点完整1公里缓冲区且类别检索已取完时，未找到设施可成为候选空白点，其余记为待核查。

## 6. 接口策略与成本

使用地点检索3.0、批量步行算路2.0、地理编码3.0、坐标转换2.0。步行批量算路按路线条数计额度和并发，默认每次1条路线、至少间隔1100毫秒；地点检索至少间隔2000毫秒。业务请求共用串行队列，从实际发出时间计算下一次发送时间，避免慢响应后的突发补发。切换5/10/15分钟和设施图层不重复测时。

单分析默认最多260条路线，每日500条路线、12次地点检索。地图之外的网络请求仅对网络故障和HTTP 5xx最多重试1次；HTTP 429或业务额度/并发错误会停止后续真实业务调用。权限错误直接返回。重试按实际路线重新记账。服务设12秒请求超时，并使用有界两分钟缓存和请求内坐标复用。

日计数写入本地`.cache/baidu-quota.json`，只保存日期和计数。应用与实测脚本默认保护值均为500条路线、12次地点检索，低于已核查的个人日配额5000条路线、100次地点检索。此记录不包含账号其他应用、其他机器的调用，平台控制台仍是最终依据。

## 7. 验证与已知限制

自动化覆盖解析三角形面积、独立片区、未知状态、跨河绕行、重复设施、坐标顺序、采样截断、河畔和边界中心、取消任务、配额恢复、重试计数、错误脱敏及HTTP生命周期。浏览器验证包括桌面操作、手机溢出、图层复用、导出、打印样式、缺失配置与错误恢复。

实际通过数量、截图和真实接口阶段记录见[验证记录](validation.md)。合成默认起点的15分钟近似可达面积约2.27平方公里，范围内9处设施，仅用于可复现回归，不是上海实测结果。

上海候选入口已完成[24点留出对照](experiments/shanghai-comparison.md)。15分钟加密轮廓一致23/24，规则网格22/24，直线圆16/24；5分钟加密19/24，规则网格21/24，不能声称加密全面占优。所有验证点与既有测时点至少相隔10米，原轮廓保持不变。24条新路线无重试，最短发送间隔1104毫秒，无新增POI检索。参考值仍来自同一地图API，入口与设施需要现场核验。

增强版新增条形图、分类核查网格、最多5份结果记录、默认零调用回放、失败保留旧结果、预算展示、启动前预算检查和同项目真实调用进程互斥。多源清洗规则见[清洗策略](poi-cleaning.md)，尚未接入第二来源实际数据。

随后完成[5分钟边界复核](experiments/shanghai-refinement.md)：复用旧记录、增加44个训练点，在预先固定的另一组24个短距离点上，一致数由20/24变为21/24；漏判4→2，误判0→1。提升有限，不能推及其他社区。新点都在10分钟内，不能验证10、15分钟边界。

目前未完成：现场核验、第二来源POI采集、更大范围的独立验证、人口加权覆盖、无障碍专用路线、施工感知、自动选址、多租户鉴权、跨机器账户配额协调、Docker实际构建及正式提交安排。

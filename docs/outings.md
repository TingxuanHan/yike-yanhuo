# 出门办事：四个生活场景

本版同时提供原生微信页面与Web页面。小程序从“附近 → 出门办事”进入，Web从“我的日常 → 出门办事 · 熟路与歇脚”进入。无服务器时，示例计算、私人熟路编辑和休息点登记可在本机使用；真实新路段和跨设备同步需要连接同一个后端。

## 一趟办齐

需要按商品和预算安排买菜、小店购物时，从本页进入[顺路好买](shopping.md)。它比较私人记录中的商品单价和整趟时间，返回每站购买清单、预计支出与返程；不将店铺消费参考或缺失价格直接当作商品报价。

选择买菜、取药、逛公园、去常去的小店中的1—3件事，设置从出门到回来的总预算，以及每站停留时间。候选地点的营业时间选填；空白会明确标为未确认。时间不足时，结果列出可完成的部分任务和未安排的任务。

每件事最多比较两处候选，三件事合计最多五处候选；真实报告使用其中已有的设施，私人小店来自地点簿。算法枚举这些候选的顺序和任务子集，先按完成任务数、再按总耗时排序，保留最多三个方案。结论仅针对本次候选，不声称找到整个城市的最优行程。

各段路和返程分别读取方向正确的路线距离。用个人步速估算走路时间，加入停留、用户填入的营业等待和可选等灯假设；到下一段时沿用已经经过的时间。支持跨午夜营业窗口，不把地图的总耗时再除以步速或重复加等灯。此版不提供实时营业或逐路口导航。

## 家人带过的路

按走路顺序写下2—8个关键点：认准哪里、到这里怎么走、入口或地标照片，以及实际走访日期。草稿在本机保留。保存后，小程序逐步显示大字卡，Web显示整条路线并支持打印；两端均可复制文字。

熟路由本人或协助者记录，不根据定位自动判断走到哪一步。照片使用既有压缩流程，每张最多64000字符的JPEG/PNG数据URI；与地点簿共用750000字节总容量。整个地点簿最多保存12条熟路。删除可撤销，恢复单条记录不会覆盖删除后其他已保存修改。

这些记录随私人地点簿手动同步到已配对设备。配对具有整个空间的读写权限；熟路目前没有独立的只读链接。现有七天只读分享接口仍只分享单个地点。

## 走走歇歇

选择目的地，设置每次最多连续走多久、每次休息多久，从最多三个休息点中比较去程。每段必须符合连续步行上限；结果显示在哪歇脚、总用时和最长连续步行时间。站着等红灯不计作坐下休息。

实际休息点先在私人地点簿记录位置，再填写本人核验日期、有效期和座位提醒。有效期最长90天，到期或位置与核验记录不一致的点不参与规划。登记表示使用者确认，不是平台对无障碍通行或实时座位可用性的认证。地点簿最多保留30个休息点。

## 补点看变化

选择药店、菜市场或小学，以及私人地点簿中的一个候选位置，比较新增设施前后各测试点到设施的步行用时。真实模式从报告的有效采样点中按固定顺序选取最多六个点，同类现有设施最多三处，界面展示对照名单。

结果给出新增覆盖的测试点数、时间缩短的点数、完整对照点平均节省时间，以及逐点前后值。任何一条现有对照路线缺失时，该测试点保留“待确认”，不能计作补点收益；新增路线也缺失时不编造结果。原始体检、公共设施清单和已有覆盖结论保持独立。

这里的数量是选定测试点，不是居民人数、社区面积或整个社区的覆盖率。候选地点是假设新增，不表示真实开业。

## 用量与数据

- 示例路线在客户端构造，无需AK或网络。
- 已获取的成功路线按有向坐标对缓存24小时，最多256段；坐标变化即不复用。离线示例与真实坐标分开。
- 真实路线每个HTTP请求最多六段，一次规划最多32段；客户端顺序分批，服务端继续共用现有百度串行队列和持久化预算。
- 整趟办事最多30段，休息点比较最多20段，六点补点对比最多24段；实际请求数受缓存、重试和坐标转换影响。不是每次点击都会消耗这些数量。
- 读取前检查含一次重试的预算余量；停止后不发下一批。当前已发出的批次可能继续完成，不能把“停止”理解为已经产生的用量可以退回。
- 真实报告是历史基础数据，新路段只在主动计算时读取。未接入实时行人红绿灯、营业状态、无障碍路段或实时座位信息。

## 不开云服务的演示步骤

1. 一趟办齐：示例街区、09:00、1.2米/秒、45分钟、买菜5分钟和取药3分钟。首选约30.2分钟，含返程；把预算改成5分钟应提示没有可行方案。
2. 家人带过的路：创建两步示例卡，退出再进入确认草稿保留，保存后查看下一步。Web打开同一记录时可打印。演示照片若使用插图，应明确说明不是现场入口。
3. 走走歇歇：示例口袋花园，连续最多走6分钟、每次歇2分钟。可得到歇脚一次约10.3分钟的方案；取消所有休息点后，当前条件下无可行方案。
4. 补点看变化：示例药店，门槛15分钟、步速1.2米/秒且关闭等灯。六个测试点中新增覆盖3个、5个时间缩短，平均节省约9.3分钟；改为20分钟时，新增覆盖变为0。上述数字仅用于复现合成场景。

真实新路线尚未用百度实测，本轮开发和验证的真实百度调用为0。已有首页切换由使用者报告手机预览正常；新增四项功能目前经过原生模拟器、自动业务测试及Web布局检查，仍需新一轮手机体验和上海现场记录。

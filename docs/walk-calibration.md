# 实走记录、步速建议与后续验证

功能基线：`541d9cf`，2026-10-16。Web与微信原生开发版共用计算、校验和私人地点簿同步；无需地图AK、模型或定位权限。

## 解决的问题

手填一个步速很难知道是否适合本人；按一次总用时倒推，又容易把等灯、办事和休息都算成走得慢。本功能把准备时的预测和走完后的记录分开，逐渐积累相近路况的本人数据。每本私人地点簿只有一组日常步速，记录必须属于同一位出门者；家人可以代填，不应混入自己的步速。

中位数是已有统计方法。本项目的贡献在于：同一套规则贯通两端、保留预测时点与历史引用、把未知来源排除在校准之外、用后续记录成对比较，并把采用建议留给用户确认。不能据此声称首创统计方法或已经提高真实人群精度。

## 操作

1. Web：我的日常 → 出行偏好 → 实走记录与步速校准。微信：我的 → 实走记录与步速校准。
2. 选择已量长度的平路，例如标有长度的步道。填写简称、50—5000米的距离及来源，核对是同一位出门者的日常走法，再点击“准备记录，固定预计用时”。此时保存预测；可以离开页面，未完成记录保留。
3. 在安全位置使用秒表或自己的计时记录；页面不自动计时、不跟踪位置。走完填写总秒数和其中等灯、休息、办事秒数。纯步行时间为两者的差。
4. 累计至少3次、合计300米的有效记录后查看建议。只有“采用建议步速”才会修改日常偏好；已有行程和报告保留原值，需要重新核算。原有交替步行偏好仍按其自己的设置。
5. 得到建议后再准备新的记录。新记录会同时保存当时设置的预测与历史建议的预测；完成后才比较误差。用于训练的前三条不会被当作自己的验证结果。

地图估算距离与模拟练习可记录，但不会进入步速建议。原有“100米换算”和行后记录仍是单次手工参考，不会被自动导入本功能作为独立测量。

## 规则与证据边界

- 仅使用已完成、明确标为已量距离、日常走法的记录；未来时间、90天前记录、主动排除记录及0.3—2米/秒之外的换算值保留明细，但不纳入建议。
- 有效步速排序后取中位数；偶数次取中间两值平均。最大/最小步速比超过1.5时暂不给建议。3次、300米、90天和1.5倍是产品保护规则，尚未做群体验证。
- 1公里用时参考来自本组最慢/最快步速，等灯和停留另计。它是样本变化范围，不是置信区间，也不保证以后能按时到达。
- 准备时固定`baselineMps`、`calibratedMps`、`trainingIds`和`startedAt`；补记只增加实际时间。建议必须来自严格早于准备时间的完整记录，已完成记录不能覆盖原预测。
- 对照只使用同一批合格后续记录，计算两种预测与实际纯步行秒数的平均绝对误差（MAE）。缺失、晚于准备、错误来源、已排除或与建议不符的历史引用不进入对照。当前设置可能已是用户采用过的建议，因此不是恒定1.2米/秒基线；固定仿真对照另有说明。
- 排除必须填写原因，原始记录仍可查看、导出和恢复。恢复重新核对条件。后续走法改变可能使建议更差，两边误差都保留。
- 距离、用时、身份与路况是本人填报，不是GPS轨迹、独立测量或防篡改凭证。没有自动验证入口、真实行人信号或无障碍通行。

## 数据、同步与容量

`LifeBook.walks`为可选字段，旧地点簿仍兼容。最多30条；上限不自动删除训练依据。准备记录、实际记录和原始预测都随既有私人空间同步，不进入邻里公开反馈、家人只读地点卡或模型提示。

Web可导出独立`yike-walk-validation-v1` JSON；微信可复制对照摘要或完整记录。完整导出含简称与时间，不含坐标、电话、照片或整本地点簿；分享前检查简称。容量满或需要重新积累时，先导出/复制保存，再明确确认清空。清空只改变本机实走记录，保留日常偏好和其他内容；通过同步页同步本机修改才更新服务器。再次合并旧备份会重新带回旧记录，不存在跨设备删除墓碑。

合并时，已完成记录优先于旧的未完成副本。同编号但准备参数不同，或两端填入不同实际时间，均拒绝合并并要求分别备份后选择版本。既有HTTP409保护避免用旧版本覆盖服务器。数据写入成功后才更新画面；失败保留输入。

## 现场证据采集提纲

选择已知长度的平地，并由同一位使用者完成。先记录3次、至少300米作为历史；再提前准备3次新的验证记录，不能先看到实走结果再选择建议。每次保留原始计时、距离依据、等灯/休息秒数及排除理由。记录缺失、路况变化和建议变差的情况，不只挑改善样本。公开前去除能定位家庭的简称，征得参与者同意。

这一步需要实际走路者完成。软件能准备记录、固定预测、导出对照和整理材料，但不能代替实走产生现场结果。

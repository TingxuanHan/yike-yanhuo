# 邻里提醒

在地点详情或一趟出门的步行指引中展开“邻里提醒”，查看其他使用者最近遇到的未开门、入口受阻、施工、台阶或路面不平。两端共用同一套规则与后端；简易首页的出门、地点和家人入口保持不变。

## 使用流程

1. 在“我的日常／我的 → 设备与同步”连接私人空间。共享提醒即使在本机服务也要求设备会话。
2. 选择地点，或为行程取得一段步行指引，再展开邻里提醒。读取只在展开或主动刷新时发生。
3. 选择“报告遇到的情况”，核对公开地点、情况类型、亲见或转述、实际发生时间及简短说明。可进一步填写入口／一段道路、具体名称与方向。明确勾选分享后才发送。
4. 其他空间可以反馈“仍有问题”“已经恢复”或“不能确定”。同一私人空间的多台设备只保留一份最新反馈。
5. 可保存本机草稿、刷新汇总或撤回自己的反馈。撤回不删除其他人的记录；发送失败保留表单，重试复用请求编号。

地点簿、入口照片、家庭位置卡和联系方式不会随上报自动公开。公开地点名称和说明由使用者核对；本版不支持附件或照片上报。

出门页面可设置少走台阶、推车、歇脚需要，相关反馈在本机突出显示，证据状态不因此升级。确认身处一个地点后，可以从提醒进入[下一站备选比较](trip-alternatives.md)，先看时间和缺价，再决定是否更换目的地。入口名称与方向是使用者填写的描述，不能把参考坐标当成已测绘的门口或道路侧别。

## 可信程度与时间

提醒采用可解释的规则，没有把分数包装成真实概率，也没有声称账号数等于已经核验的独立人数。

| 近期有效反馈 | 显示方式 |
| --- | --- |
| 一份亲见问题 | 单份反馈，待核实 |
| 至少两个空间亲见问题，且没有恢复反馈 | 多份近期反馈 |
| 同时有亲见问题和恢复反馈 | 近期反馈有分歧 |
| 只有恢复反馈 | 有恢复反馈，待核实 |
| 只有转述或不确定 | 待确认，不提升亲见计数 |
| 有效观察已过期 | 过往反馈，不作为当前问题 |

有效期从实际观察时间计算，重复上传不会延长旧观察的有效期。不同情况采用不同时间窗口：

| 情况 | 有效期 |
| --- | --- |
| 这次到店未开门 | 6小时 |
| 入口受阻 | 12小时 |
| 施工 | 48小时 |
| 台阶或门槛 | 7天 |
| 路面不平 | 72小时 |

页面读取满5分钟或最早一份观察到期时提示重新读取，不静默请求网络。没有提醒不代表营业或通行正常，恢复反馈也不能代替现场确认。

## 与路线的关系

地点提醒匹配目的地100米内的记录；道路类情况也匹配已取得的路线折线40米内的记录。未开门只关联目的地附近，不扩散到整条路。临近可能是道路另一侧、另一个入口或不同楼层，因此文案明确要求核对，不自动绕路、不改变原行程和历史报告。

百度步骤只有在每步均有完整坐标、至少两个点、相邻步骤相接不超过10米、合计不超过2000点和35公里时才用于沿途匹配。任何一步缺失、坐标混乱或断裂，就保留文字指引并退回目的地匹配，不将缺口连成直线。路线字段依据[百度步行路线接口](https://lbsyun.baidu.com/docs/webapi?title=directionlite/guide/webservice-lwrouteplanapi/walk)中的步骤路径与坐标系参数。

BD-09在本机转为GCJ-02后匹配；WGS-84不会直接与GCJ-02混算。已有路线有明确返回坐标时，使用其终点和路径查询。模拟社区与真实地点严格分开，模拟记录在界面标注。

## 服务与存储边界

- 所有共享读写要求设备会话；配对设备共用空间身份。服务端只在内部保留空间身份摘要，不向其他使用者返回设备令牌、空间编号或私人地点簿。
- 更新和撤回带版本号，冲突返回409；请求编号防止网络重试重复写入。私人数据同步与公共提醒是不同接口。
- 每空间每分钟最多120次查询、12次写入，每天最多40次共享操作；达到每日上限后仍允许撤回本人反馈。单次查询最多返回50个相关事件并提示截断；全服务最多5000个事件。
- 长期没有更新的事件保留30天；请求回执与审计记录保留30天。仍然活跃的事件保留各空间的最新观察，不能据此承诺所有相关数据都在30天后自动删除。
- 查询坐标不保存为轨迹，不进行后台定位或消息推送。规则计算、坐标匹配和反馈操作不调用百度、模型或语音服务。
- 当前是邀请使用的单实例原型，尚未提供公开注册、真人身份核验、刷号治理、管理员审核与申诉后台。公共开放前需补齐治理流程。

本机可以用两个独立浏览器会话验证跨空间提醒。不同网络中的Web和微信设备需要连接同一个可达的HTTPS服务；这次实现不等于已经部署云服务或发布小程序。

## 验证与后续

自动化验证覆盖观察时间、不同空间计数、转述、恢复冲突、撤回、过期、位置与路线匹配、缺失路径、幂等重试、限流、重启持久化、鉴权及Web／微信实际业务代码。浏览器检查320像素布局、草稿恢复、错误保留、只看台阶和双用户流程。具体结果见验证记录。

测试使用构造数据，不构成实际社区事件或现场通行证明。下一步应先做手机与真实街道试用，验证入口定位、有效期是否合适和老人是否能理解分歧提示，再考虑照片证据、治理后台与人工复核。

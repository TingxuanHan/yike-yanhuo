# 下一站的备选安排

在“一趟出门”已经确认所在地点、尚未前往下一站时，展开“下一站不好走？看看备选”。Web与微信共用选择、计算和确认逻辑。邻里提醒中也提供这个入口。

## 操作

1. 可在“我的通行需要”选择尽量少走台阶、推车出门或需要歇脚。设置随私人地点簿同步，用于突出相关反馈，不是已核验的无障碍路线条件。
2. 选择“换同类地点”，从已有报告或本趟候选中选未安排的同类地点；或选择“用我记录的另一入口”，从私人地点簿选本人确认属于原目的地的点。模拟场景提供明确标注的示例入口。
3. 比较当前点到备选点、备选点到后续站点的两段路线。真实模式先检查缓存，未缓存的路段需要确认后才读取百度；沿用全站串行和持久化额度。
4. 核对剩余路程、用时、预计返回时刻和整张购物清单的已记录价格。未记录价格显示待确认，不显示零元预算；原店报价不套给新店，已购与实付金额另行确认。需要歇脚者还应计入未建模的额外停留。
5. 明确确认后才替换下一站。取消、缺少路线、时钟异常或比较超过5分钟均保留原行程。行程进度改变后必须重新比较。
6. 重新准备出门卡，并查看新路段指引及邻里提醒。旧卡会标为过时；此前已到达的地点、事件和原方案保留。

同类候选距原地点最多2公里，另一入口参考点最多500米；两者要求坐标可比较。每趟最多保留五个地点、五条替换记录。容量不足时只移除未使用的比较候选，不删除已规划、已走或跳过的地点历史。换过地点的行程不会直接保存为原方案的常用快捷方式。

## 入口和道路侧别

邻里反馈可填写“入口”或“一段道路”、具体位置名称及东／西／南／北侧。不指定时保持原有地点提醒。这些字段帮助使用者理解说的是哪一处；坐标仍是地点或路线的参考点，不能声称已经测绘出门口坐标、道路另一侧或障碍面。东门与西门记录分别汇总，临近匹配仍要求使用者核对。

本功能更换目的地，不会要求百度绕过任意上报障碍，也不保证另一入口可走。通行偏好不提升反馈可信程度；单份、分歧、恢复和过期状态继续按已有规则呈现。

## 本轮验证

上海API用例为抚顺路社区睦邻中心至阳普鞍山菜市场，再比较美城菜市场。原往返410米，备选往返496米；备选去程248米、地图参考232秒，返回3条文字指引和18个路径点。本轮实际消耗5次路线调用，重复比较和指引读取命中缓存，未追加搜索或底图请求。

这是2026-10-15的API验证；入口、营业、无障碍和现场通行尚未实走核实。机器记录见实测摘要，脱敏后的公开地点回放见回放输入。模拟反馈不是实际用户报告。

界面：320像素备选比较、入口反馈与分歧。
